Designing reliable webhooks for AI workflows

Mubarak IbrahimNovember 2026Technical design and engineering practice

An AI workflow often looks synchronous in a demo but asynchronous in production. Identity checks, document processing, payments, and recruitment workflows depend on external services that can delay, retry, or deliver events out of order.

Separate event delivery from workflow state

A webhook is a notification, not necessarily proof that a business process should advance. Persist events, verify them, then apply explicit state transitions. A valid signature establishes provenance and integrity; it does not establish that the event is timely, relevant to a tenant, or permissible in the current state.

HMAC verification

Sign the raw request body with an agreed secret and compare the expected digest using a constant-time comparison. Include a timestamp and rotate secrets through a defined transition period. Never trust a client-provided tenant identifier without binding it to the verified integration credential.

import hashlib
import hmac

def verify_signature(raw_body: bytes, signature: str, secret: bytes) -> bool:
    expected = hmac.new(secret, raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)

This minimal example does not include timestamp validation, replay protection, canonical encoding, or secret rotation. Add these before using the approach in a production integration.

Make processing idempotent

Persist each provider's event ID with a uniqueness constraint scoped to the integration or tenant. If the same event arrives twice, return an appropriate acknowledgment without replaying side effects. Handle concurrency at the database boundary rather than relying on in-process locks.

Retries should be finite and observable

Use exponential backoff with jitter, classify transient versus permanent errors, and send exhausted deliveries to a reviewable failure queue. Do not retry invalid signatures or events that can never pass validation. Track the age of the oldest unprocessed event as well as the raw failure count.

Out-of-order events

An older “pending” event can arrive after a “completed” event. Define valid transitions and version conditions in the workflow state machine so an old notification cannot undo a terminal decision.

Production checklist

Verify authenticity, identify the tenant, deduplicate events, enforce state transitions, persist outcomes, and log a traceable correlation ID without exposing sensitive payloads.

Lessons from identity and AI integrations

These patterns are particularly important for workflows that combine document extraction, verification providers, and downstream business applications. The architecture should withstand duplicate delivery, temporary outages, and delayed callbacks without losing the transaction's history.

This article describes general engineering patterns, not the private implementation of any employer or client product.
